> 范围：lib 337 个 Dart 文件（约 1.9 万行）、test 134 个文件（739 用例）、CI 三条流水线

## 一、项目整体情况

### 1. 技术形态
Flutter 3.47 背单词 App（fork 自"不背单词"），Supabase 后端 + 本地 SQLite 词库，目标 Windows 桌面 + Android(arm64)。发版走 CI tag 流水线（Setup exe / aab / split-per-abi apk），本地守护 739 个测试 + 多道架构门禁。

### 2. 目录结构与模块职责

```
lib/
├── app/            # 组合根：Provider scope 嵌套（11 层）+ 路由
├── core/           # 基础设施 + DI(get_it) + 学习算法引擎 + 五套仓储
├── features/       # 11 个业务特性（多数为 domain/application/data/presentation 四层）
│   ├── learning    # 学习主流程 —— 全库枢纽（被 189 处跨模块消费）
│   ├── settings    # 学习偏好 + 提醒调度（端口-适配器范式的标杆）
│   ├── checkin / scare_coin  # 签到与尖叫币（v2.7.32 已统一为单一事实来源）
│   ├── book / content / dictionary / quick_review / search / word_browse / account
├── widgets/        # 33 个跨 feature 共享组件
├── models / theme / tokens / utils # 根级辅助目录
```

### 3. 依赖关系
- **规则**：跨 feature 只能 import 对方 `application/` 端口（R4，由 `test/architecture/import_guard_test.dart` 在 CI 强制）。
- **数据流**：UI(Provider scope) → application 端口 → data 适配器 → 本地存储/远端。
- **实际扇入**：learning 被依赖 189 处，是事实上的核心枢纽；app.dart 允许直取 presentation（组合根特权）。

## 二、审计发现（按严重程度排序）

### 🔴 严重（建议本批/下批立即处理）

**S1. 发版链路可绕过测试门禁**
- `release_packages.yml`（tag 触发）只 `flutter pub get` 后直接构建三端产物，**不跑 analyze/test**；`build.yml` 只 analyze 不测试。
- 后果：tag 一旦推错，坏代码可直发版。此前所有批次的测试通过是因为我们手动先跑——流程靠纪律而非机制。
- 建议：release_packages.yml 构建前加 `flutter analyze` + `flutter test` 两步（成本 +5~8 分钟，可接受）。

**S2. 整文件死代码约 1100 行**
- `lib/widgets/path_marquee.dart`（396 行）：全项目零引用。
- `lib/widgets/spring_calendar.dart`（~250 行）：SpringCalendar/MiniSpringCalendar 均无调用方。
- `lib/tokens/gameboy.dart`（36 行）：GameBoyPalette 零引用。
- `lib/widgets/morphing_tabs.dart` 内 MorphingTabs/MorphingTabIndicator（~330 行）：仅 SimpleMorphingTabs 被 lib_select_page 使用，其余死。
- 建议：一批删净（morphing_tabs 拆出 SimpleMorphingTabs 单独成文件）。

**S3. core → feature data 依赖倒置（架构根基问题）**
- `lib/core/di/service_locator.dart:8-15`：core 直接 import `features/book/data/`、`features/learning` 等——core 反向依赖 feature，分层名存实亡。
- 建议：组合根上移至 `lib/app/`（app 本就是组合根层，无新增违规）；core 只留基础设施。

**S4. 签到双数据源修复无回归测试守护**
- `docs/regression_ledger.md` 只登记到 REG-REM-001（第二十批），v2.7.32 签到修复无台账条目、`test/regression/` 无 checkin 用例——违反"每个已修复 bug 必须有永久回归测试"的自定原则。
- 建议：补 1 条回归用例（签到→历史页读到同一条记录）+ 台账登记。

### 🟠 高

**H1. `scripts/import_checker.py` 是死脚本**
- 第 154/246 行硬编码旧机器路径 `D:/claude/work/cn_com_lange/word_app`，只扫早已废弃的 `lib/pages|screens`，且无任何 CI 引用。真正的门禁是 `import_guard_test.dart`。
- 建议：直接删除，消除"有守卫"的假象。历次发版日志里它显示"0 循环依赖"实为空跑。

**H2. appearance_page 壁纸/阅读模式预览卡断线**（遗留项 #6）
- `appearance_page.dart:98-221`：静态假卡片，硬编码 `Color(0xFF87CEEB)` 渐变，不读状态、无交互。
- 建议：删除（主页已按方案 C 无壁纸，预览卡无存在意义）。

**H3. Provider scope 嵌套顺序靠注释维护、无测试锁定**
- `lib/app/app.dart:40-63`：11 层 scope，注释自述"[1]~[4] DAG 链序选择，非依赖驱动"。learning 被 189 处消费，其 scope 一旦挪位即全库碎，且无测试报警。
- 建议：写 1 个架构测试锁定 scope 顺序（与 app_structure_test 同类）。

### 🟡 中

**M1. feature 内部结构不齐**：11 个 feature 中 content 只有 presentation 层；scare_coin、word_browse 缺 domain 层。建议按需补齐或在架构文档明示豁免，不强制形式对齐。

**M2. DI 双轨存量**：get_it（基础设施）+ Provider（ChangeNotifier）分工已有注释约定，但 `dictionary_by_name_page`、`word_lookup_popup` 两处 presentation 仍直取 `sl<>`；`if (!sl.isRegistered)` 防重注册模式脆弱。建议收口到 Provider。

**M3. lib/widgets 绕过端口直取 feature presentation**：`review_dialog.dart:6-7` 直取 learning/presentation；根级 widgets 目录不在任何 guard 覆盖内。建议把 review_dialog 移入 learning feature 或走端口。

**M4. 主题三层色值重复**：`skin_system.dart` 7 套皮肤硬编码（L126-349）与 `starbucks_tokens.dart` 数值重复，`design_tokens.dart:10-51` 再转发一遍，`func_colors.dart` 语义又重叠。单一事实来源破口。建议以 skin_system 为准收敛 tokens。

**M5. 硬编码颜色散布 presentation 层**：home_screen(6 处)、check_in_history_page、app_dock.dart:100,191、bending_gallery、fluid_cursor 等十余处 `Color(0x…)` 绕过皮肤系统，切肤时会露馅。建议专项收敛。

**M6. `_CoinCard`/`_EquipCard` 复制分叉**：`profile_screen.dart:302/359` 与 `my_space_page.dart:300/347` 各自实现同功能卡片，且后者用 ThemeVars 绕过 SkinSystem。建议抽共享组件。

**M7. data_verification 偶发失败根因确认**：`wordbook_database.dart:93` `initialize()` 的 `if (_initialized) return` 是 check-then-act 竞态，无互斥锁；且全量跑每次解压 35MB 词库造成 I/O 竞争。建议加 Completer 互斥 + 测试共享预解压 fixture。

### ⚪ 低

- **L1** 目录职责重叠：`lib/models/`（11 个模型与 feature domain 重复）、`theme/`+`tokens/` 并存、`utils/` 仅 1 文件。建议逐步归位。
- **L2** 日期解析重复：`my_fav_sentence_page.dart:310` 与 `word_detail_notes_section.dart:231` 各手写 substring 解析。抽 util。
- **L3** SP key 散落：`redemption_center_page.dart:87/104`、`lib_select_page.dart:657/662` 未集中到 `app_preferences.dart`。
- **L4** `test/pages/` 存有按"修复批次"命名的大杂烩测试（account_fix6、ux_fix_c），与 lib 无镜像；根级 `data_verification_test.dart` 建议归位 `test/quality/`。
- **L5** 命名风格整体一致（camelCase/snake_case 文件名遵守良好），`ScareCoin`（尖叫币）拼写虽怪但是既定产品词，不算缺陷。
