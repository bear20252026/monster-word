## 二、全库重新扫描：架构问题列表（附位置）

### 🟠 A1（中·偏高）：星巴克主题"两套真相"且已经漂移
- **位置**：`lib/theme/skin_system.dart:204-275`（两套 preset 全量硬编码）vs `lib/tokens/starbucks_tokens.dart:9-120`（token 唯一定义）
- **实证**：skin_system **根本没 import** starbucks_tokens（:1-6），同一"星巴克奶油主题"两套色值已分叉——accent `0xFF006B3F`(:217) vs token `0xFF00754A`(:21)；success `0xFF2E7D32`(:218) vs token `0xFF4CAF50`(:28)；dark accent `0xFF00BB00`(:254) vs token `0xFF00A862`(:81)；text2 透明度也不同（0xB3 vs 0x94）。
- **后果**：换肤走 skin、代码消费走 token，两路数据不一致，单一事实来源在此彻底断裂。
- **建议**：按已拍板的 ⑥-1 方案执行——token 采用 WCAG 修正值，skin preset 改引 token 常量，加守卫测试断言 preset==token。**这是当前唯一"已拍板未动工"项，建议作为下一批立即执行。**

### 🟠 A2（中）：widgets/ 层完全脱离 ImportGuard 约束（新发现的结构性缺口）
- **位置**：`lib/core/import_guard.dart:53`（`_featureOf('widgets/…')` 返回空串 → isCrossFeature=false 直接放行）
- **实证**：`lib/widgets/review_dialog.dart:6-7` import learning 的 **presentation 内部**（learning_session_state.dart + review_page.dart）并在 :27-28 直接 `context.watch<LearningSessionState>()`——共享组件层穿透到 feature 页面内部，R4/R6/REG-ARCH-002 三个守卫都抓不到。
- **建议**：把 import_guard 的 from 域扩展到 `widgets/`（规则同 R4：只许 application 端口），review_dialog 移入 learning feature 或改为消费端口。

### 🟠 A3（中）：R6 DI 豁免通道被 presentation 滥用（上轮 M2 恶化）
- **位置**：`features/learning/presentation/personal_stereo_page.dart:10,37,64`（import app/service_locator + `sl<AudioService>()`、`sl<NewWordsReader>()`）
- **实证**：R6 豁免本意是 data 适配器经 `fromServiceLocator()` 走 DI 契约，现在 presentation 页面开始走同一条豁免通道规避 Provider；`import_guard.dart:13-14` "存量仅 2 处"注释已失真（实际 3 处：dictionary_by_name_page.dart:42、word_lookup_popup.dart:102、personal_stereo_page.dart:37,64）。
- **建议**：① personal_stereo_page 改 Provider 注入（新增违规应优先消灭）；② 另两处存量收口；③ 补一条规则测试锁定"presentation 禁 import app/service_locator"。

### 🟡 A4（中）：11 层 scope 全序仍未锁定（上轮 H3 半修复）
- **位置**：`lib/app/app.dart:42-84`（现 12 层） vs `test/architecture/app_structure_test.dart:379-383`（仅 indexOf 锁 ScareCoin→CheckIn 一对）
- **后果**：learning 被 189 处跨模块消费，其 scope 挪位 = 全库运行时 ProviderNotFound，编译期静默。
- **建议**：写全序断言（一个测试锁定 [1]~[12] 的 indexOf 递增），10 分钟工作量，性价比极高。

### 🟡 A5（中）：_CoinCard/_EquipCard 双写已分叉（上轮 M6）
- **位置**：`features/account/presentation/my_space_page.dart:300/347/396` vs `features/settings/presentation/profile_screen.dart:302/359/409`
- **实证**：装备数规则 `1 + (redeemed>0) + (streak>0)` 两处各写一遍；UI 已漂移（MwCard+RouteNames vs 裸 Container+字符串路由 `'/scare_coin_history'`）；`_equipIcon` 两份实现签名不同。
- **建议**：抽 `features/account/presentation/scare_coin_summary_card.dart` 共享组件，settings 侧消费它。顺带消灭 profile_screen.dart:313 的字符串路由。

### 🟡 A6（中）：initialize 并发竞态（上轮 M7 未动）
- **位置**：`lib/core/infrastructure/wordbook_database.dart:93-95`（`if (_initialized) return` 后多个 await，:193 才置位；`_rebuilding` 只护 forceRebuild 不护 initialize）
- **建议**：Completer 互斥（~10 行）；测试 fixture 共享预解压词库。

### 🟡 A7（低~中）：lib/models/ 实为"全局共享 domain"，边界模糊（上轮 L1 升温）
- **位置**：`lib/models/word.dart`（被 98 个 feature 文件直接依赖）；`models/definition.dart` 与 `features/dictionary/domain/definition_item.dart` 并存
- **建议**：不急于大迁移；先在架构文档（architecture_boundaries.md）明示"models/ = 跨 feature 共享域模型，feature 自有 domain 仅限 feature 内部"的定位，防止继续双向滋生。

### ⚪ A8（低）：presentation 超大文件集中
- 前 10 大文件全部 600~780 行且 8 个在 presentation 层（learn_page 778、more_settings_page 770、lib_select_page 721 等）。可读性可维护性尚可（方法级拆分尚清楚），但趋势值得留意。
- **建议**：不专项处理；立规"新页面单文件超 600 行需说明理由"，随功能迭代自然拆分。

### ⚪ A9（低）：装饰色硬编码无豁免规则（上轮 M5 现状）
- features 33 处/9 文件（应清零）；widgets 58 处/15 文件中 word_globe.dart 16 处、confetti.dart 12 处为粒子特效装饰色（实质可豁免但无规则区分）。
- **建议**：M5 专项时区分"语义色必须走 token"与"特效装饰色可白名单豁免"，避免为豁免而放松主干。
