## 2. 视觉回归方案（轻量替代）

现状：没有现成的截图对比工具链，不为此引入重型基建。三层递进：

### 2.1 Golden 测试起步（自动防线）

- 对**设计系统组件**（skin_system 的主题 token 消费方、widgets/ 下卡片/按钮类组件）建 `test/goldens/`：
  - 每个核心组件至少 2 个 golden：默认态 + 主要交互态；
  - Token 层改动后跑 `flutter test` 即可发现颜色/字号/间距的意外漂移；
  - 更新流程：有意变更时跑 `flutter test --update-goldens`，golden diff 必须在 PR 里说明并经 QA 确认。
- 注意：golden 在 Windows 本地生成，团队统一在 Windows 上维护，避免跨平台字体渲染差异造成假阳性。

### 2.2 手动检查单 per 页面（每层改完执行）

每页固定 6 项：①布局无溢出（看右下角黄黑条纹）②文字截断/换行正常 ③深浅色下对比度可读 ④点击热区反馈正确 ⑤转场动画不闪跳 ⑥空态/加载态有兜底。

### 2.3 关键页面截图存档（docs/screenshots_before_after/）

- 存档对象（重构前必须先拍）：启动页、Home（home_screen）、学习答题页（learn_session）、字典弹窗（WordDictionaryPopup 展开态）、复习页（review_session）、听写页（spell_session）、收藏页（my_fav）、统计页（dashboard）、设置/外观页（appearance_page）。
- 命名规范：`{页面}_{主题}_{before|after}.png`，如 `home_themeA_after.png`；皮肤系统共三主题，Home 与学习页三个主题各拍一张，其余页面拍默认主题即可。
- 时机：每个页面开工前拍 before，页面层完成后拍 after，成对放入同一目录，QA 用肉眼 A/B 对照归档结论。
- 工具：Windows 截图即可（Win+Shift+S），不追求自动化。

## 3. 核心流程冒烟清单（合并前必过）

> 前置：干净安装/清缓存启动一次（首装路径），另备一份有历史数据的设备（升级路径）。每条含操作步骤与预期结果。

### 3.1 词书加载
- 步骤：启动 App → 通过启动页进入词书选择（lib_select_page / books_page）→ 选择一本词书下载/导入 → 返回书架查看。
- 预期：下载进度正常走到 100%；书架出现该书且词条总数显示正确；点进 book_words_page 能看到单词列表；杀进程重开后书还在（本地库持久化 OK）。

### 3.2 学习答题（选错重选 / 选对进字典）
- 步骤：Home → 进入学习（learn_page / learn_session）→ 故意选错选项 → 观察反馈并重选至答对 → 答对后点击单词弹出字典（WordDictionaryPopup）→ 查看释义后关闭 → 连续完成一组学习 → 中途退出 App 再进入。
- 预期：选错时该项标红且允许重选，不计为掌握；答对后计数 +1、进度条推进；字典弹窗内容与词条一致；中断后再进能恢复进度，已完成的不重复计。

### 3.3 复习
- 步骤：Home → 进入复习（review_page / review_session）→ 完成全部到期卡片的复习动作 → 结束后回到 Home / dashboard。
- 预期：复习队列数量 = dashboard 显示的"待复习"数；完成后 SRS 状态更新（下次到期时间顺延）；复习结果反映到统计页。

### 3.4 听写
- 步骤：进入听写/拼写字典（spell_session_page / spell_check_page，列表听写走 list_word_listen_page）→ 播放发音 → 键盘拼写提交 → 故意拼错一次再看判分 → 完成一节。
- 预期：发音可播（音频资源加载正常）；拼写判分准确，错字母高亮；拼错的词进入生词/未掌握集合；会话结束给出正确率。

### 3.5 收藏
- 步骤：在学习页或字典弹窗内收藏一个单词 → 进入 my_fav_page 确认出现 → 取消收藏再确认消失；对例句做同样操作核对 my_fav_sentence_page。
- 预期：收藏/取消即时生效；杀进程重启后状态保留；收藏页点条目能跳回对应详情。

### 3.6 统计
- 步骤：完成上面 3.2/3.3 的操作后进入 dashboard_page → 核对各数字 → 切换日期/周期视图（如有）。
- 预期："今日已学/已复习"与刚才实际操作次数一致；图表渲染无溢出、无 NaN/负数；离线打开统计页不崩溃。

## 4. 分阶段回归节奏

按重构层次递进，下层不稳不上层：

| 阶段 | 改完立刻测（快速环） | 阶段收尾测（完整环） |
|---|---|---|
| **Token 层**（skin_system.dart、theme、颜色/字体/间距常量） | `dart analyze`（红线 G1/G2）+ 全量 `flutter test`（含 golden）+ 三主题切换目检（appearance_page / ui_theme_select_page 来回切，重点看 Home 和学习页配色是否串味） | §2.2 手动检查单扫全部关键页面 + §3 冒烟 3.2/3.6 抽查 |
| **组件层**（widgets/ 下通用组件、glass_widgets 等） | analyze + test + **用 grep 找出该组件的全部使用方**，只对使用方页面做视觉检查（§2.2 六项） | 受影响页面对应的 §3 流程项 + 截图 after 归档 |
| **页面层**（pages/、screens/ 单页改造） | analyze + test + 该页面完整手动检查单 + 该页面所属核心流程的 §3 条目 | 合并前跑全量门禁（G1–G5）+ 当日所有改过的页面截图 after 入库 |

节奏约定：
- 每个功能分支合入前：快速环。
- 每完成一层：完整环 + QA 更新 issue 计数台账（对照 368 基线）。
- 高危区文件（§5）改动不受此表约束，一律走专项流程。

## 5. 高危区专项保护

基线中 issue 最密集的三个 service 文件，是全局共享的单点依赖，重构它们的风险远高于 UI 层。

### 5.1 通用要求（三者都适用）
- 改动必须**独立成 commit**（不与 Token/组件/页面混提），commit message 注明 `[high-risk]`。
- 动手前先为其**补最小单元测试**（纯 Dart 可测，mock 网络/平台通道），先绿后改。
- 重构前后用日志对比法：开启请求/任务日志，录一份 before 行为样本存 `docs/fixtures/`，after 逐条比对。
- 改完除常规门禁外，加跑一次真机完整 §3 冒烟（这三个文件影响所有在线流程）。

### 5.2 lib/services/http_client.dart（41 issues）
- 风险：超时/重试/错误处理逻辑散落，重构易改变网络行为。
- 保护：
  - 单测覆盖：超时抛错、非 200 处理、重试次数上限三类场景的行为在重构前后一致；
  - 断网/弱网手册验证：飞行模式开关 + net_diagnosis_page 自检通过；
  - 抓包或日志比对重构前后请求 URL、header、编码完全一致。

### 5.3 lib/services/background_service.dart（35 issues）
- 风险：后台调度时机敏感，且与锁屏模块（lock/）联动，坏了表现为"静默失效"。
- 保护：
  - 前后台切换测试：App 退到后台/回前台各 10 次，任务触发时机无重复、无丢失；
  - 与 lock_service 联动场景：锁屏出现/解锁后服务恢复；
  - 长时间挂机（≥30 分钟）观察内存不涨、任务按时执行。

### 5.4 lib/services/api_services.dart（18 issues）
- 风险：接口契约漂移会导致登录、词书下载等主链路全断。
- 保护：
  - 契约冻结：把重构前的真实响应 JSON 存入 `docs/fixtures/`，重构后解析结果逐字段 diff 必须一致；
  - 三个必测接口：登录鉴权、词书列表/下载、统计上报——每个都过一遍成功 + 服务端报错两分支；
  - 监控错误提示文案：用户可见的报错信息不得因重构变成裸异常文本。
