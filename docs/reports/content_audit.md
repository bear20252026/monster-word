## 一、词书数据库抽检

### 1.1 数据文件清单

| 文件 | 大小 | 说明 |
|---|---|---|
| `assets/db/wordbook.db.gz` | ≈32.7 MB | gzip 压缩的 SQLite 库；应用首启时由 `WordbookDatabase.ensureReady()` 解压为 `wordbook.db`（≈121 MB）后以**只读模式**打开 |

检查方法：将 `.gz` 解压至系统临时目录（项目外），用 `sqlite3 "file:...?mode=ro"` 只读打开，检查完毕已删除临时副本。

### 1.2 表结构与行数

| 表 | 行数 | 字段 |
|---|---|---|
| `books` | **191** | id, code (UNIQUE), name, word_count |
| `words` | **32,154** | id, word, main_word, interpret, uk_pron, us_pron, phrase, example, confuse, audio_urls, image_urls, word_root |
| `word_books` | **454,196** | 词↔书多对多关联 |

结构性结论：
- ✅ `word_count` 与 `word_books` 实际关联数**全部一致**，无虚标；
- ✅ `words.word` 无重复拼写（32,154 行 = 32,154 个 distinct word），有索引 `idx_words_word`；
- ⚠️ 空字段用**占位符字面量**填充（`""`、`[]`、`{}`）而非 NULL，任何按「非空即有数据」做的统计或 UI 判断都会误判。

### 1.3 全局字段质量（words 表，N=32,154）

| 指标 | 数值 | 占比 |
|---|---|---|
| 完全没有释义的词 | **20,006** | **62.2%** |
| 有释义但缺音标 | 1,512 | 4.7% |
| 音频 URL 为真实内容 | 14,560 | 45.3% |
| 图片 URL 为真实内容 | 14,307 | 44.5% |
| 词根词缀为真实内容 | 6,715 | 20.9% |

### 1.4 抽检两本词书

**① CET4DGCH（id=7，「CET4 高频词汇」，4,755 词）**

| 字段 | 齐全数 | 齐全率 |
|---|---|---|
| 释义 interpret | 3,395 | 71.4% |
| 英音 uk_pron | 3,395 | 71.4% |
| 美音 us_pron | 3,395 | 71.4% |
| 短语 phrase（剔除占位符后） | 3,395 | 71.4% |
| 例句 example（剔除占位符后） | 3,395 | 71.4% |
| 形近词 confuse（剔除占位符后） | 3,387 | 71.3% |

**② SAT（id=133，「SAT 核心词汇」，10,001 词）**

| 字段 | 齐全数 | 齐全率 |
|---|---|---|
| 释义 interpret | 5,509 | **55.1%** |
| 英音/美音 | 5,509 | 55.1% |
| 短语/例句/形近词 | 5,509 | 55.1% |

关键发现——**双峰分布**：所有内容字段呈「整组有、整组无」的模式。一个词要么释义+音标+短语+例句+形近词齐全，要么只剩拼写、其余字段全是占位符。缺失不是随机散布，而是按批次/来源成块缺失。

### 1.5 数据层最大问题：词书名 = 编码码

`books.name` **191 本全部等于 `code`**。用户在选书页（`lib_select_page.dart:341`）和词卡组件（`adapter_widgets.dart:407`）直接看到的是 `HZBCET6N`、`RJB7NJX` 这类内部编码，而非「六级核心词汇」这样的友好名称。封面文字仅做了 `MonsterWord_` 前缀剔除（`_coverText()`），治标不治本。这是比任何文案风格问题都严重的内容硬伤。

## 三、品牌语言建议（Monster Word × 咖啡馆氛围）

以下仅为**建议清单，未做任何改动**。原则：中文为主、咖啡隐喻点缀，避免为了氛围牺牲功能可理解性。

### 3.1 主入口（优先级最高）

| 现文案 | 建议 | 说明 |
|---|---|---|
| `Learn` | **「今日现磨」** 或「学新词 · 现磨」 | 新词=新豆现磨，副标题可保留「学习新词」兜底 |
| `Review` | **「续杯」** 或「复习 · 续杯」 | 复习=续杯回甘，天然契合记忆曲线 |
| 「开始使用」(splash) | 「欢迎光临 Monster Café」 | 首启更有门店感 |
| 「开始学习」 | 「开始冲煮」/「来杯今日单词」 | 任务书中示例方向，成立 |
| 「继续学习」 | 「续上刚才那杯」 | 断点续学场景 |
| 「开始复习」 | 「温一杯旧的」 | 复习的温暖表达 |
| 「再来一轮」 | 「再续一杯」 | 与「续杯」体系呼应 |
| 「重新开始」 | 「换一杯新的」 | 拼写测验失败重试场景 |

### 3.2 功能命名微调

| 现概念 | 建议 | 说明 |
|---|---|---|
| 签到 | 「打卡领豆」 | 可顺势引入咖啡豆积分体系，把签到变成有奖励的动作 |
| 生词本 | 「想再尝一口」/「待品清单」 | 若嫌长可保留「生词本」，副标题用咖啡馆语言 |
| 已学单词（「全部已学单词」） | 「喝过的都记着」/「我的咖啡档案」 | 足迹页语境下更有人味 |
| 今日已学 | 「今天喝过的」 | 口语化但不失清晰 |
| 词根词缀课 | 保持现状 | 「图记单词」已足够好 |

### 3.3 提示语方向

- 网络错误类：在标准提示后补一句轻量安抚，如「网络好像断电了，稍后再试」→ 更贴题的：「咖啡机暂时离线，检查一下网络？」（视品牌尺度取舍）；
- 完成类：完成一轮学习可用「这杯做好了 ☕」替代干巴巴的「完成」。

⚠️ 改文案前先修 1.5 的词书编码名问题——名字是「HZBCET6N」的词书配上再温暖的按钮文案也无济于事。
