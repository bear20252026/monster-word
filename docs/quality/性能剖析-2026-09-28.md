## 核心发现

1. **卡顿全部在光栅/合成侧，不在 build 侧**：五场景 build P95 全部 <2ms（widget 逻辑健康），而滚动场景 24% 帧超预算、raster P95 是 build P95 的 5~6 倍。**归因修正（09-28 深挖）**：Dock 本身无模糊；真凶是 `GlobalNavHistoryBar` 常驻 pill 的 `BackdropFilter(12)`（桌面端 MaterialApp.builder 层常驻，底层内容一变即逐帧重光栅化）——已实施滚动降级（滚动中近实底、静止恢复）。次要嫌疑为卡片阴影 overdraw。
2. **Tab 切换首个大帧 108.9ms**：首次装配 LibSelectPage（网格 + CurrentBookHero + FlowIn 波次 + Dock 模糊层）的一次性行，伴随 **RSS +203MB 的跳变**——这条内存跳变最扎眼，需要专项复测归属（模糊层 / 封面解码 / Transform 层保存）。
3. **两个滚动场景同步 24% 超 17ms**：词书网格与单词列表超帧率高度一致，指向**公共层**（Dock 模糊 + FlowIn Transform 入场期间的层合成）而非单页问题；34ms+ 深卡顿少（网格 0 次、列表 6 次），观感应为"轻微不跟手"而非"可见卡顿"。
4. **列表滚动 +84MB**：200 词窗口懒加载 + FlowIn 入场，量级可接受但方向值得留意。
5. **启动 762ms + 首屏 max 371ms**：冷启动整体健康；首屏第一个大帧由首页装配 + 入场波次构成，桌面端无感，移动端复测时需关注。

## Dart 堆 vs native 拆分（09-29 · VM Service 实测）

| 检查点 | RSS | Dart 堆（heapUsage） | 堆容量 | external |

| 启动完成 | 276 MB | 15.5 MB | 17.2 | 0.01 |
| 启动首屏 | 358 MB | 21.2 MB | 24.2 | 0.02 |
| Tab切换→课程 | 381 MB | 25.8 MB | 26.7 | 0.03 |
| 词书网格滚动 | 539 MB | 22.3 MB | 25.2 | 0.02 |
| 进入单词浏览页 | 574 MB | 28.0 MB | 31.2 | 0.03 |
| 单词列表滚动 | 721 MB | 27.1 MB | 32.2 | 0.03 |

**结论：** RSS 全程增长 +445MB，而 Dart 堆始终 15~28MB 且不随滚动单调增长（21→28→22→28→27 波动即 GC 稳态），external（IO/typed data）≈0——**内存增长 ~97% 在 native/驱动侧**（引擎光栅缓存、层缓冲、交换链），与"滚动期新内容首次绘制的有界缓存"归因互相印证；**不存在 Dart 侧泄漏**。native 侧增长有界且平台策略性缓存，桌面端（通常 ≥16GB 内存）无需干预；若未来移动端紧张，方向是引擎光栅缓存上限，而非应用代码。

## 入场"会话内一次"与残余 jank 收口（09-29）

词书单词页与句库页入场波次改为**每条内容在页面会话内只入场一次**（`_enteredWordIds` / `_enteredSentenceKeys`，滚动往返/勾选等重建走静终态）——既是光栅收敛（滚动期不再产生新 Opacity 层重放），也是交互正确性修复（此前滚回顶部内容会重新闪动，违反 motion 克制原则）。复测：词表 jank17 **17→11**、total P95 **20.9→15.0ms**；残余 11 帧（4.7%）为文本行+圆角+图标的光标本底，收益递减，收口。

## 内存跳变归因（09-29 · harness 归因段实测）

| 步骤 | RSS | imageCache |
|---|---:|---|
| 切换前（学习 Tab） | 361 MB | 0 张 / 0 MB |
| 切换后 250/500/750ms | 391 → 398 → **412 MB** | 0 |
| 切换后 1s~3s（7 个采样点） | 412.4~412.8（走平） | 0 |
| 清图像缓存后 | 412.9（无回吐） | 0 |
| 切回学习 Tab(1s) | 418.6（不回落） | 0 |
| 二次进入课程 Tab(1s) | 414.4（不再跳变） | 0 |

**结论：**

1. **排除图像解码**：全程 imageCache 为 0（封面是纯色容器，页面无 ImageProvider），清缓存无回吐；
2. **"+203MB" 已被 PR #87 回收**：pill 模糊降级后 Tab 切换步仅 +52MB（361→413），首修前同步 551MB——大头正是常驻 BackdropFilter 的离屏+模糊缓冲（Windows 侧按屏面尺寸分配）；
3. **剩余大增量在滚动期**（网格 +152MB / 列表 +103MB），且与首跑终点一致（~568 vs ~565）——是滚动时新卡片首次绘制产生的光栅缓存/saveLayer 分配，**有界、可复用、不随滚动无限增长**（多场景终点稳定），无泄漏特征；
4. **切回不回落、二次进入不跳变**：分配被框架/驱动缓存保留复用，属正常策略而非泄漏；
5. Dart 堆与 native 的进一步拆分需交互式 DevTools（P3 留档）。
