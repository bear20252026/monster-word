# 聚宝日历签到页 · 设计要点与区别性论证（结合整个 App 设计）

> 目的：把"这一个单独页面"放进"整个 App 的设计语言"里论证区别性——避免被认定为"孤立花齿造型"而撞车 cojeev-ui。

## 一、本设计是「App 整体设计语言的体系化落地」，而非孤立元素

整个 App（Monster Word）采用一套可识别的视觉体系：
- **星巴克式暖纸设计系统**：暖纸画布 `#f2f0eb / #edebe9`、品牌绿 `#006241` 仅用于主操作与当日描边、金色仅用于奖励语义——这是贯穿全 App 的色彩纪律。
- **专属吉祥物"肚皮储蓄罐"**：青绿圆身、橙角橙脚、黑豆眼微笑、胸前奶白 W 纹（W 呼应 App 图标），是 App 的视觉资产。
- **花齿印章日期徽章**：本页独创的 12 瓣平滑花齿造型，是这套体系在"签到/日历"场景的延伸。

本签到页 = 上述**三项体系资产在单一界面的协同呈现**。这种"整体一致性"本身即构成对一般消费者的明显区别性，因为竞品（含 cojeev-ui）只是通用组件库，**没有品牌色彩纪律、没有储蓄罐叙事、没有签到语义**。

## 二、与现有设计的区别对照（细化版）

| 对比项 | cojeev-ui（最接近现有设计，2026-09 MIT 公开） | 常规日历签到页 | **本设计（结合 App 整体）** |
|---|---|---|---|
| 基本单元 | 通用 UI 卡片 / daisy-12 花形（幅度≈29%） | 方格/数字 | 12 瓣平滑花齿印章（幅度≈12.5%）+ 聚合时花齿⇄方章双轮廓渐隐 |
| 单元数量 | 6–10 个卡片零件 | 28–31 固定格 | 28–31 个可移动花齿徽章 |
| 色彩语义 | 通用调色板，无品牌纪律 | 红点/对勾 | 暖纸底 + 品牌绿仅 CTA/当日 + 金仅奖励（App 全局纪律） |
| 聚合目标 | 零件拼成一张卡片 | 无（静态网格） | 漂浮徽章聚合成月历网格 |
| 粒子行为 | 环绕零件边缘、落位淡出 | 无 | 环绕 → 螺旋吸入徽章中心 → 签到时为金币吸入储蓄罐 |
| 终止语义 | 无 | 点格打勾 | 徽章碎化为金币 + 生物储蓄罐吸入充盈（App 吉祥物联动） |
| 品牌叙事 | 无 | 无 | "喂食—存储"闭环，与 App 吉祥物一致 |

## 三、参数级差异化（对抗 cojeev-ui 同族造型的关键）

- 花齿幅度：`amp/R ≈ 0.125`（细腻含蓄）vs cojeev-ui `daisy-12` 约 `0.29`（夸张）。
- 附加形变特征：本设计在聚合落位时**花齿轮廓渐变为圆角方章（双轮廓交叉渐隐）**，cojeev-ui 无此过渡。
- 结论：即便审查员认为"花齿造型"与 daisy-12 属同族，本设计的**参数差异 + 形变特征 + 整体构图/状态序列/储蓄罐联动**仍足以形成明显区别。

## 四、请求保护重心的写法（落到申请文件）

- **写进设计要点**：花齿印章造型、散落⇄聚合双构图、底部储蓄罐插画及联动、整体色彩基调（见 `03_简要说明_正式稿.md`）。
- **不写进设计要点**：连续签到"火苗图标"（行业惯常，多邻国等已有，纳入易被抗辩）。
- **视图呈现**：五幅图须贯穿同一套 App 色彩纪律与储蓄罐形象，让"整体一致性"在图中自证。

## 五、与 App 其它资产的互补保护建议

| 资产 | 建议保护类型 | 理由 |
|---|---|---|
| 花齿印章徽章图形 / 肚皮储蓄罐插画 | **著作权登记**（登记制、成本低、即时生效） | 固定图形作品权属 |
| "Monster Word" 名称 + 肚皮形象 | **商标**（第 9 类软件 / 第 41 类教育） | 品牌识别 |
| 本签到页界面构图 | **GUI 外观设计专利**（本文档） | 界面视觉卡位 |
| 签到玩法/算法（如有技术效果） | 视情况 **发明/实用新型**（非本任务范围） | 方法层保护 |

三层互补，避免把"品牌识别"误塞进外观专利而导致要点被削弱。
